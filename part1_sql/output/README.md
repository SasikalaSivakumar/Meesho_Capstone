## Technical Note: Why `COUNT(*)` Cannot Detect Zero-Match LEFT JOIN Rows

When performing a `LEFT JOIN` between `resellers` and `orders`:
- For reseller `RS024` (who has placed zero orders), the `LEFT JOIN` preserves `RS024` by returning a single unmatched row where all columns from `orders` (e.g., `order_id`, `category`, `unit_price`) are filled with `NULL`.
- `COUNT(*)` counts the number of physical rows produced by the join query. Because one row exists for `RS024` (with `NULL` order attributes), `COUNT(*)` evaluates to **1**.
- `COUNT(o.order_id)` specifically evaluates expressions, ignoring `NULL` values. Because `o.order_id` is `NULL` for `RS024`, `COUNT(o.order_id)` evaluates to **0**.

### Key Takeaway
Using `COUNT(*)` on a `LEFT JOIN` result group will falsely report 1 order for resellers who have never placed an order. To accurately detect zero-match cases in SQL, analysts must use `COUNT(column_name)` on a non-nullable column from the right table (e.g. `COUNT(o.order_id)`), or use a `WHERE o.order_id IS NULL` clause.
